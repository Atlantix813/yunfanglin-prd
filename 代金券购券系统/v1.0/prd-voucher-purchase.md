# 代金券购券系统

> 需求文档 · v1.0 初稿（2026-08-10 立项）
> 模式：大型功能版

## 需求背景

### 项目背景

云芳邻当前优惠券体系是"免费领取 / 积分兑换 + 到店核销"，平台无法从发券和核销中产生收入，商家券兑现是平台无法验证的线下事件。商业模式探索已确认：免费券做不了收入，付费券是唯一通路——只有用户在线付钱，平台才有资金控制权，佣金才能自动扣取。

天河金融城共建研讨会确定乐维转为自营运营制，先在小范围跑通"购券—到店消费—核销—分账"的商业闭环。本版本建设付费代金券购券系统，对标掌上生活、大众点评的代金券玩法：商家发布"40 元购 50 元"类代金券，居民在线微信支付购券，到店核销，核销即分账。

代金券与现有优惠券是**两套独立系统**：代金券属于商品 + 订单体系，居民在【我的订单】查看；优惠券仍是直接领券逻辑，在【我的卡包】查看。两者底层执行逻辑不同，本期不做合并。

**资金与进件选型（2026-08-10 立项评审确认，2026-08-18 修正）：** 原定平台收付通（电商收付通）方案，因服务商号下已有越景特约商户（注销也不行）无法开通，**退回普通服务商特约商户模式**——平台入驻普通服务商，商家进件为微信特约商户，用户支付资金进入**商家特约商户号**并冻结，核销后由平台发起分账，将抽佣分到平台商户号，剩余资金解冻归商家。商家侧需完成微信进件（提交资质 + 微信审核 + 商家扫码签约），平台在系统内提供**运营代办进件**功能，不建设商家自助申请页。该选型替代 CRMEB 参考系统"平台统收 + 线下打款"的二清模式，资金由微信托管，合规干净。

## 需求目标

### 核心目标

1. 建立完整的付费代金券交易闭环：商家发券 → 居民购券 → 在线支付 → 到店核销 → 核销即分账。
2. 平台取得真实交易收入：核销完成后平台发起分账，从商家特约商户号将抽佣分到平台商户号，平台得抽佣，商家得实付扣除抽佣后的金额（解冻后按微信侧规则提现）。
3. 资金与退款合规：支付与分账走微信支付普通服务商模式，资金在商家特约商户号冻结托管，退款支持微信原路退回与平台线下垫付两类通道，平台不代收代付商家货款。
4. 商家准入与进件：系统内提供运营代办进件功能，运营录入商家资料并调微信进件接口，跟踪申请单状态后回写特约商户号；不做商家自助申请进件。

### 验收标准

1. 订单主状态只有：待付款、待使用、退款中、已核销、已退款、已关闭。
2. 免费券不创建支付、分账和退款记录；免费券过期页面展示"已过期"（底层状态待使用）。
3. 退款记录创建后，订单进入退款中且不可核销（核销码隐藏、核销接口拒绝）。
4. 未核销订单支持用户和平台发起退款。
5. 已核销订单只能由平台创建退款记录（居民联系客服）。
6. 未核销和已核销未分账均走微信全额退款（不允许部分退款）。
7. 微信退款最多自动重试 3 次。
8. 微信退款失败后订单不自动回退，售后转"退款失败待人工"进入人工处理。
9. 已核销未分账退款成功后，分账记录改为"已终止（退款）"。
10. 已核销已分账退款走平台线下垫付。
11. 已核销已分账不调用微信退款，不做分账回退。
12. 平台垫付完成后订单为已退款，售后状态为"已退款待追回"。
13. 追回不设置部分追回状态，金额纯人工留痕。
14. 分账任务只判断"分账状态为待分账且达到预计日期"。
15. 分账任务不判断订单主状态。
16. PC 支持对三种退款场景发起和处理退款。
17. 居民只有未核销待使用订单显示申请退款。
18. 所有退款记录都能查看对应分账信息（按订单 ID 关联）。
19. 页面按钮、状态标签、流程图与 PRD 完全一致。

## 业务流程总览

### 主流程

1. 商家发布代金券：设置券名、面额（如 50 元）、售价（如 40 元）、库存、有效期、使用说明（含使用条件，如满 80 元可用）。
2. 居民在【代金券】列表浏览，进入详情页查看券信息与商家信息，确认购买。
3. 居民提交订单并发起微信支付，支付成功后订单进入 [待使用] 状态。
4. 居民到店消费，结账时出示核销码，商家扫码核销，券面额（50 元）抵扣账单。
5. 账单抵扣后的剩余金额由商家线下补收，不走云芳邻。
6. 核销成功后自动发起分账：平台从商家特约商户号将抽佣金额分到平台商户号，剩余金额解冻留在商家特约商户号可用余额。
7. 订单进入 [已核销] 状态，居民收到核销成功通知。

- 商家进件主链：**串行主线 + 超管异步引导**——提交创建申请单 → 超管扫统一链接核对联系信息（不影响审核）→ 平台审核（1-3 工作日，通过/驳回分支）→ 审核通过后判定是否账户验证（法人本人当超管免验证；需验证主体完成汇款/法人扫码）→ 签约 → 开通权限 → 特约商户号回写；超管侧全部操作通过同一链接按状态分步引导。
- 进件异常分支：审核驳回（同编号覆盖重提）、30 天作废（重新发起新申请单）。
- 结算账户修改子流程：商家申请 → 微信审核（可打 0.01 元验证新卡）→ 驳回重发 / 成功回写；每天限 5 次。
- 商家注销子流程：清账校验五清单 → 微信注销申请（审核中/驳回换单/成功）→ 遗留资金全额清退 → 商家状态转已注销。
- 商家发券：按券类型（免费/付费）与进件完成状态分流，付费券需进件完成，提交后平台审核。
- 免费券领取：0 元订单，无支付、无分账、无退款；过期仅状态标记。
- 到店核销：校验订单归属、订单状态、有效期；核销成功后付费券进入分账、免费券无资金流。
- 分账（分账记录视角）：付费券核销 → 创建分账记录（待分账）→ 是否延长分账（PC 人工）→ 到达预计分账日期由每日分账任务执行（唯一条件=待分账且到期，不判断订单主状态）→ 已分账 / 分账异常。「已终止（退款）」不经过分账流程：退款审核通过走微信退款成功那一刻，由退款流程回写分账状态，此后记录不再满足待分账条件，任务天然不执行。
- 退款（三分支，先判断单状态再判触发方）：① 订单未核销（待使用）——用户申请创建退款记录（免审核，自动通过）直接微信退款；平台/系统创建（过期任务等）创建退款记录后走人工审核；两条路都先创建退款记录（订单转退款中、核销码隐藏）；② 订单已核销——退款仅平台/系统触发（居民联系客服），创建退款记录后人工审核，通过后按分账状态分流：待分账走微信退款（成功后分账记录回写「已终止（退款）」节点转终态），已分账走平台垫付（垫付弹窗审核通过即视为垫付完成，不调微信退款、不分账回退），售后转「已退款待追回」；③ 追回为一次性动作：与商家线下协商后，追回弹窗一次回填实际追回金额/追回时间/备注，保存后售后转「已追回」（无部分追回、无全额判断），平台损失=微信手续费+商家未追回金额。

### 资金流转

| 环节 | 资金去向 |
| --- | --- |
| 居民支付 40 元 | 进入**商家特约商户号**（下单时传分账标识），处于冻结状态，商家不可动用 |
| 未核销期间 | 资金冻结在商家特约商户号，居民可申请退款（从冻结资金直接原路退）或等待过期自动退款 |
| 核销成功 | 平台发起分账：抽佣金额从商家特约商户号 → 平台商户号（准实时到账，平台可提现）；剩余 40 − 抽佣（扣除支付手续费后）自动解冻留在商家特约商户号 |
| 商家收款 | 商家所得在特约商户号可用余额，商家按微信侧规则提现到结算银行卡（平台可通过提现引导支持） |
| 退款 | 未核销/已核销未分账：微信原路全额退款（分账记录转「已终止（退款）」）；已核销已分账：平台线下垫付（不调微信退款、不分账回退），后续与商家线下协商追回 |

### 与现有优惠券系统的边界

- 代金券：商品属性，走订单支付流程，在【我的订单】查看，核销后触发分账。
- 优惠券：领取属性，在【我的卡包】查看，核销后无资金流，本期不做任何调整。
- 两者的核销码、核销入口、页面归属完全独立，不共用状态和记录。

### 技术实现要点

> 方案：**微信支付 · 普通服务商特约商户模式**（2026-08-18 评审确认：收付通因服务商号已有越景特约商户无法开通，退回普通服务商）。前置条件：平台入驻普通服务商（服务商商户号），商家进件为特约商户；资金进入特约商户号并冻结（分账冻结期 30 天），核销后平台发起分账抽佣。接口清单参考普通服务商特约商户进件与分账 API。

#### 进件与支付

1. 前置开通：平台入驻普通服务商（服务商商户号），无需收付通工具箱；普通服务商下特约商户支持 API 进件（`POST /v3/applyment4sub/applyment/`）。
2. 商家进件：运营在 PC 端【商家进件】填写结算账户与超级管理员，调普通服务商特约商户进件接口创建申请单；跟踪申请单状态，完成后回写特约商户号。进件审核 1-3 个工作日；商家超管需微信扫码签约（实名校验一致）；部分主体需汇款验证或法人扫码（期限 10 天，普通服务商口径）。
3. 支付下单：采用服务商普通支付（JSAPI/小程序支付），下单时传商家特约商户号和分账标识，用户支付资金进入商家特约商户号并冻结（**分账冻结期 30 天**，普通服务商口径；非收付通 180 天）。
4. 回调校验：支付回调验证签名与金额，回调与主动查询结合确认支付结果，防止丢单。
5. 待支付订单超时未支付自动关闭，释放库存。

#### 分账流程

1. 核销成功后平台发起分账：按订单实付金额与抽佣比例计算抽佣金额，分账方向为"商家特约商户号 → 平台商户号"（普通服务商分账，平台作为服务商发起）；剩余未分账资金自动解冻归商家。
2. 分账金额不得超过"订单实付 − 支付手续费"的净额；分账比例默认上限 30%（特约商户授权"允许服务商分账最大比例"，超管可在商户平台调整）。
3. 分账状态跟踪：分账请求（异步受理）→ 查询分账结果（按接收方 result 判断成功/失败）→ 失败自动重试（原单重试），仍失败进入人工处理。
4. 支付手续费：按结算规则在结算时由微信扣取（费率档位由进件 settlement_id 确定，未传默认 0.6%）；普通服务商下分账本身免费。

#### 退款与垫付

1. 未核销退款与已核销未分账退款：调用微信退款 API 全额退款（金额固定为订单实付金额，不允许部分退款）；未核销订单资金从特约商户冻结资金原路退回；已核销未分账订单审核通过时若分账仍为待分账则同样走微信退款，微信退款成功后分账记录转「已终止（退款）」。
2. 已核销已分账退款：不调用微信退款 API、不执行分账回退（微信侧交易与分账均保持已完成）；平台线下向居民垫付退款，审核通过即视为垫付完成；后续平台与商家线下协商追回，追回金额人工留痕。
3. 退款幂等：同一退款单不允许重复发起，退款结果通过回调与主动查询确认；微信退款失败自动重试最多 3 次，仍失败转人工处理（订单保持退款中，不自动恢复）。
4. 过期自动退款：定时任务扫描 [待使用] 过期付费券订单批量创建退款单并走微信退款；免费券不创建退款记录。

#### 提现与账户

1. 商家所得解冻后进入特约商户号可用余额，商家在微信支付商户平台自行提现到结算银行卡；平台提供余额查询（调微信余额查询接口）与提现引导，不代管商家资金。
2. 平台抽佣进入平台商户号可用余额，平台按微信侧规则提现到对公银行卡。

#### 对账与失败处理

1. 每日对账：支付单、分账记录、退款单与微信侧资金账单核对（冻结/解冻在基本账户内部不生成账单记录，分账划出生成支出记录），金额不一致标记异常。
2. 异常处理：分账失败、退款失败、金额不一致订单进入 PC 端异常列表，支持【重新分账】与人工处理。
3. 交易记录保存不少于三年，符合电商交易信息留存要求。

#### 幂等与安全

1. 下单、支付回调、核销、分账、退款均按业务主键做幂等处理；分账请求失败按原单重试，不重复创建分账单。
2. 核销码不可猜测，核销时校验订单归属、商家归属、状态与有效期。
3. 用户与商家仅能访问各自维度的订单数据，PC 端按组织树权限控制。
4. 商家敏感进件资料（身份证、银行卡）按最小权限保存，PC 端按角色权限可见。

【我的】页「代金券」模块订单状态入口（待付款 / 待使用 / 已退款 / 全部订单）进入。

#### 页面目标

集中展示居民购买的全部代金券订单及状态，与优惠券卡包彻底分离。

#### 页面结构

- **顶部状态 Tab**：全部 / 待付款 / 待使用 / 已核销 / 退款中 / 已退款 / 已过期（免费券），选中项黑色加粗 + 蓝色下划线，数字角标展示对应数量
- **订单卡片**（一条订单一张卡，枚举状态）：
   - 店铺名：取商家名称，左上黑色加粗
   - 状态：右上角文字（按状态枚举）：
      - 待使用：蓝色文字
      - 已核销：绿色文字
      - 已退款：灰色文字
      - 已领取（免费券）：绿色文字
   - 券名：取订单券名，两行内省略
   - 有效期：待使用订单显示"有效期至 X 月 X 日"，到期前 3 天红色高亮"剩 3 天"
   - 金额：付费券取售价红色加粗；免费券显示"免费"绿色；已退款显示划线原价
   - 操作按钮（按订单状态 × 售后状态枚举）：
      - 待付款 → 【继续支付】
      - 待使用 + 无售后 → 【出示核销码】（蓝底白字）+【申请退款】（白底描边，点击弹退款原因弹窗）；免费券显示"已领取"标签，【出示核销码】为绿色底白字
      - 退款中（待审核/微信退款中/退款失败待人工）→ 不显示核销码，【联系客服】
      - 已核销 → 【查看详情】【联系客服】
      - 已退款（已退款/已退款待追回/已追回）→ 【查看详情】
      - 已关闭 → 【查看详情】
      - 免费券过期 → 页面展示"已过期"标签（底层状态仍为待使用，无操作按钮）
   - 卡片点击：整卡可点击进入订单详情页（按钮点击不触发卡片跳转）
- **空状态**：无订单时居中显示"暂无订单" + 引导文案"去逛逛市集，买一张超值代金券吧"

#### 展示规则

1. 列表按订单创建时间倒序。
2. 状态 Tab 数字角标展示对应数量。
3. [待使用] 订单展示剩余有效天数，即将过期（3 天内）高亮提示。
4. 免费券过期不创建退款记录、不进入退款中/已退款，页面按有效期展示"已过期"；付费券过期由系统自动创建退款单走微信退款。

#### 操作说明

1. 点击订单卡片进入【居民端订单详情页】。
2. 点击【出示核销码】展示大号核销码供商家扫码。
3. 点击【申请退款】进入退款确认（未核销订单可用）。

#### 异常提示

空订单时展示空状态与引导"去逛逛代金券"。

#### 数据写入

无新增写入，仅读取订单列表。

#### 页面位置

由【居民端我的订单页】点击订单卡片进入。

#### 页面目标

完整展示单笔订单的状态、券信息、核销码、核销记录与退款信息。

#### 页面结构

**状态区**
- 订单状态与说明：按状态枚举
  - 待使用：大字"待使用"（黑色），小字"到店结账时出示核销码，商家扫码核销"
  - 已领取（免费券）：大字"已领取"（绿色），小字"免费券已生成订单，到店出示核销码"
  - 已核销：大字"已核销"（绿色），小字"核销时间 X 月 X 日 · 门店名"
  - 已退款：大字"已退款"（灰色），小字"退款金额 ¥40 · 原路退回微信支付"
  - 退款中：大字"退款中"（橙色），小字"退款处理中，暂不可使用"；隐藏核销码区与申请退款按钮
  - 已过期（免费券）：大字"已过期"（灰色），小字"免费券已过有效期"

**核销码区**（[待使用]/[已领取] 显示，其他状态整区隐藏）
- 核销码数字：大号等宽加粗 30px，字母间距加宽，如"8890 6623 4410"；取当前核销码字段，60 秒自动刷新
- 提示文案：灰色小字"核销码每 60 秒自动刷新"，位于码下方
- 手动刷新：常显（与自动刷新并存），点击立即刷新；刷新失败保留旧码并提示"刷新失败，请手动刷新"

**券信息区**
- 券名：取订单快照券名
- 有效期至：付费券"购买后 22 天内有效" / 免费券"领取后 22 天内有效"
- 使用说明："每单限用 1 张；超出面额部分到店补收"

**商家信息区**
- 商家名：取商家名称
- 地址：取门店地址
- 电话：蓝色可点击，点击调起拨号

**金额区**
- 实付金额：付费券红色加粗 ¥40；免费券"免费（¥0）"绿色
- 平台服务费：付费券"已含在商家结算中"；免费券 ¥0
- 分账金额：付费券 ¥2.00；免费券 ¥0

**操作区**（底部固定，按钮按状态枚举）
- 【出示核销码】：[待使用]/[已领取] 显示，蓝底白字，点击进入亮屏核销码页（全屏大码便于扫码）
- 【申请退款】：仅 [待使用] 付费券且无售后显示，白底描边，点击弹退款原因弹窗，确认后订单进 [退款中] 并关闭弹窗（系统自动审核通过，直接进入微信退款）
- 【联系商家】：所有状态显示，蓝底白字，点击调起拨号
- 【联系客服】：[已核销] 与 [退款中] 状态显示，蓝底白字，点击拉起**微信客服工具会话**（沿用平台现有微信客服接入方式，无需新建客服系统；已核销不提供退款按钮，退款中隐藏核销码）

#### 展示规则

1. 核销码：60 秒自动刷新；刷新失败保留旧码 + 手动刷新入口；过期/已核销后整区隐藏。
2. 过期处理：付费券已过期未核销 → 状态区"已过期，系统正在自动退款"（系统已自动创建退款单）；免费券已过期 → 页面展示"已过期"，底层状态保持待使用，无退款动作。
3. 取值口径：金额取订单快照（购买时固化）；日期统一"X月X日"。
4. 退款进度：退款中显示"退款处理中，暂不可使用"与"预计 1-3 个工作日到账"，隐藏核销码；退款完成显示到账结果；已退款订单不允许再次申请退款。
5. 免费券：实付/手续费/服务费/分账金额一律 ¥0，仅保留核销记录。

#### 操作说明

1. 申请退款（付费券待使用）：点击【申请退款】→ 弹退款原因弹窗 → 确认后订单进 [退款中] → 平台处理完成进 [已退款]，结果消息通知。
2. 退款原因弹窗：预设原因（暂时不想使用 / 商家诱导线下交易 / 商家拒绝履约）+「其他原因」——选择「其他原因」时显示自由文本输入框（必填，最多 100 字），用户可自行描述纠纷详情；原因随退款单写入【退款记录表】，用于平台甄别与飞单/履约问题监控。
3. 纠纷处理边界：**核销前争议走线上退款**（按上述退款流程）；**核销后争议走人工处理**（订单已核销无居民退款入口，用户通过【联系客服】进入微信客服工具反馈，由平台人工介入后在 PC 创建退款记录：未分账走微信退款、已分账走平台垫付，见【PC端退款处理页】）。
4. 核销流程：到店出示码 → 商家扫码核销 → 订单变 [已核销]，核销码区隐藏、状态区更新。
5. 免费券：无退款按钮，仅联系商家/客服。

#### 异常提示

核销码刷新失败时提供手动刷新入口。

#### 数据写入

退款申请写入退款单；核销状态由商家侧核销动作更新。

#### 页面位置

商家后台【代金券管理】内【发布代金券】。

#### 页面目标

让商家自主创建代金券商品，支持付费券（40 购 50 类）与免费券（0 元）两种类型。

#### 页面结构

- **基本信息**：
   - 代金券名称：输入框，必填，最多 20 字，占位"如：40元代50元代金券"
   - 券类型：单选切换（付费券 / 免费券），默认选中付费券；**进件未完成时付费券选项禁用**（灰色不可选）
   - 适用人群：单选（全部用户 / 仅新客），默认全部用户——**复用现有优惠券模块「新客券」能力**（新客判定：未在该商家核销过代金券）
   - 适用门店：当前店铺（商家多门店时可切换）
- **价格与库存**：
   - 券面额：数字输入，必填，如 50（免费券同样必填，用于核销抵扣与展示）
   - 售价：付费券必填（须小于面额）；**免费券隐藏该输入**，显示"免费券售价固定为 ¥0，领取后生成 0 元订单，不进入支付和分账"
   - 发售库存：数字输入，必填
   - **每人限领张数**：数字输入，默认 1；领取达到上限后券仍展示并标记「已领取」，不可再次领取（**复用现有优惠券模块限领能力**）
- **有效期**：可售时间（开始/结束，日期选择器）、使用有效期（"购买后 22 天内有效" / 免费券"领取后 22 天内有效"）
- **使用说明**：使用规则文本（多行，最多 300 字；使用条件如“满 80 元可用”、时段限制等写入规则文本）
- **抽佣提示**：付费券显示当前平台抽佣比例与示例（如"每售出 1 张预计到账约 ¥38 元"）；免费券显示绿色提示"免费券无抽佣、无分账"
- **底部操作**：【存草稿】（白底描边）【提交审核】（蓝底白字，提交后变"待平台审核"置灰）

#### 展示规则

1. 售价必须小于面额（付费券），否则提交校验失败并提示"售价需低于面额"。
2. **免费券校验**：券类型=免费券时售价固定 0，无需校验售价；面额必填（用于核销抵扣与展示"免费领 50 元券"）；新发布的免费券同样进入 [待审核]。
3. **发券权限**：开店成功（商家状态=正常）即可发布免费券、优惠券、推广；**付费代金券需完成微信进件**（已回写特约商户号），进件未完成时付费券类型不可选，提示"商家进件未完成，暂不可发布付费券"。
4. **限领与人群**（复用现有优惠券模块能力）：每人限领张数默认 1，达上限后 C 端仍展示券卡片并标记「已领取」，不可再次购买。**新客券**：C 端列表与详情对所有用户展示并带【新客券】标签；点击领取/购买时接口判断新客资格（未在该商家核销过代金券），非新客弹出报错弹窗“该券仅限新客，您已在本店核销过代金券”，不可下单。
5. 抽佣说明：付费券发布页展示当前平台抽佣比例（继承平台配置），并展示示例"每售出 1 张，商家预计到账 X 元"；**免费券无抽佣、无分账、无手续费**。
5. 新发布的代金券进入 [待审核] 状态，由平台审核通过后上架。

#### 操作说明

1. 点击【提交审核】后进入待审核状态，审核通过前商家可编辑或撤回。
2. 审核通过后不可编辑价格与库存等关键字段，需下架后编辑。

#### 异常提示

库存、有效期、价格校验失败时在对应字段下方提示。

#### 数据写入

创建代金券商品记录，状态为 [待审核]；记录 [券类型]（paid/free），免费券售价记 0。**券上不存抽佣比例**——抽佣在下单时按商家当前生效比例计算并固化到订单。

商家扫码核销居民的代金券，核销成功后自动触发分账。

#### 页面结构

1. 扫码 → 展示券信息 → 商家确认【确认核销】。
2. 核销成功后页面提示分账状态，商家无需再执行任何收款动作。

1. 收入口径（随面板时间范围统计）：累计销售额 = 范围内已支付订单实付合计（全口径）；累计解冻收入、实际平台服务费 = 已核销且已分账口径；待分账金额（在途）= 已核销待分账订单的实付合计。

9. **免费券订单**：0 元券订单不进支付与分账，订单记录保留（核销记录用于商家引流统计），实付、微信手续费、平台服务费、分账金额、商家到账金额一律显示 ¥0.00；不占用可用余额、不参与提现。

### PC端商家进件管理页

#### 页面位置

PC 后台【商家管理】新增【商家进件】。

#### 页面目标

跟进进件申请单至完成（取得特约商户号）：跟踪微信审核、账户验证、签约进度，支持签约链接获取与驳回原因查看。**发起新进件不在此页**（入口在【商家列表】）；**修改结算账户、注销为商家主体级操作**，入口在【商家列表/商家详情】，记录分别在【商家结算账户修改】【商家注销】列表页承载。

#### 页面结构

- **开店资质（只读引用区）**：商家名称、主体类型、经营者/法人、资质状态——来自创建商家时已提交的资料，本页展示但不可改。
- **进件填写信息**（在【商家列表】发起进件时填写，提交成功后生成进件记录）：结算账户类型（下拉：经营者个人银行卡 / 对公银行账户）、开户银行、银行账号、超级管理员（姓名 + 身份证 + 手机号，需与微信实名一致）——进件环节新增字段，创建商家时未收集。
- **进件状态区**：
   - 进件申请单号：取微信进件申请单号
   - **进件状态**：直接采用微信 applyment_state 枚举（8 态）——编辑中 / 审核中 / 待账户验证 / 待签约 / 开通权限中 / 已完成 / 已驳回 / 已作废（串行主线，一一对应不归并；页面展示与官方枚举一致，无归并中间态）
   - 特约商户号：进件完成后回写
   - 结算卡核对状态：一致 / 不一致（不一致高亮"商家已私下改卡"）
   - 本页仅展示已发起进件的商家记录；未发起进件的商家在【商家列表】体现
- **操作区**：按主状态动态显示操作按钮（见操作说明）

#### 展示规则

1. 进件状态流转（串行主线 + 超管异步引导）：① 提交进件调用微信申请单接口，**接口同步校验资料完整性与格式**（秒级返回；请求必下发申请单——校验通过进 [审核中]，不通过进 [编辑中]，重新提交同编号覆盖）；② **核对联系信息**：申请单创建后即可从查询接口获取签约链接（超管侧统一入口，建议转二维码发超管）——超管扫码绑定微信号并核对联系信息，不影响审核；③ **平台审核**（1-3 个工作日）；④ 审核通过后判定是否需**账户验证**（仅需验证主体）：超管用同一链接按页面指引完成验证（汇款/法人扫码，10 天期限）；⑤ **签约**：验证完成（或免验证主体）后超管在同一入口完成签约——页面步骤数随主体不同（需验证 4 步 / 免验证 3 步），一个链接贯穿全程；⑥ 签约完成 → 开通权限（约 30 分钟）→ 特约商户号回写。**全程串行推进，超管侧操作（核对信息/验证/签约）通过同一链接按状态分步引导，公众号自动推送进展。**
2. 超管填写指引：**超级管理员优先填经营者/法人本人**（用其本人实名微信操作）——法人本人当超管可**免账户验证**，签约一步到位；仅经营者不便操作时填负责人（非法人），此时需法人另行配合扫码验证，流程多一个环节。运营代办时严禁填运营自己为超管。
3. 账户验证期限 10 天（超时自动驳回）；汇款验证金额验证后自动退回，到账等待 1-2 天。
4. 未获得特约商户号的商家不能发布付费代金券，进件完成前付费券创建入口置灰并提示"进件未完成"；开店成功即可发布免费券、优惠券和推广。
5. 商家首笔交易后微信将打 0.01 元验证结算银行卡，验证失败时进件状态区提示"结算卡验证失败"。
6. 已回写特约商户号的商家即可被业务人员授权管理员与核销员。
7. 申请单 30 天未处理自动作废，状态展示"已作废"；重新发起为全新记录。
8. 已完成商家做结算账户核对：平台存档结算卡与微信侧生效结算卡不一致时，该行高亮并标记"商家已私下改卡"。

#### 操作说明

1. 本页仅展示已发起进件的商家记录；未发起进件的商家不在此页，其发起动作在【商家列表】行内【发起进件】完成。
2. 【获取签约链接】——[审核中 / 待账户验证 / 待签约] 可用；点击打开**二维码弹窗**（展示申请单号 + 二维码示意 + 操作说明），由超管微信扫码：审核中扫码仅绑定微信号+核对联系信息，待账户验证/待签约状态按页面指引完成对应操作。
3. 【驳回原因】——[已驳回] 显示，点击打开**时间轴弹窗**展示驳回信息（提交申请单 → 平台审核驳回原因详情），供运营对照修改资料。
4. 【编辑】——[编辑中 / 已驳回] 可用，点击打开编辑弹窗（结算账户 + 超级管理员信息），弹窗底部【重新提交】按钮：同一申请编号覆盖原申请单重新进入审核（已驳回弹窗顶部同步展示驳回原因）。
5. 【查询进件状态】——[编辑中 / 审核中 / 待账户验证 / 待签约 / 开通权限中] 可用，同步微信申请单状态。
6. 【删除】——已提交申请单不可删除（官方无撤销，30 天自动作废）。
7. 商家基础信息与微信进件信息支持编辑，编辑记录操作日志。
8. 修改结算账户 / 申请注销为商家主体级操作，不在本页执行——入口在【PC端商家列表】行内操作，记录见【PC端商家结算账户修改】【PC端商家注销】列表页；[已作废] 仅保留【查看进度】，重新发起进件去【商家列表】。

#### 异常提示

- 主体类型缺少对应资质资料时提示"缺少营业执照 / 经营者证件"。
- 进件被驳回时展示微信驳回原因。
- 商家未完成签约时提示"商家尚未签约，无法收款"。

#### 数据写入

创建商家记录与进件扩展字段（进件申请单号、进件状态、特约商户号、结算银行信息、注销申请状态）；复用现有商家表并扩展字段；商家扩展表承载进件资质与结算资料。

### PC端商家结算账户修改

#### 页面位置

PC 后台【商家管理】新增【商家结算账户修改】。

#### 页面目标

承载已签约特约商户的结算账户修改申请记录：发起修改、跟踪微信审核状态（审核中/驳回/成功）、驳回后重新发起。修改成功自动回写商家主记录的当前结算账户。

#### 页面结构

- **筛选区**：商家名称、申请状态（审核中/审核驳回/审核成功）、提交时间范围
- **列表**（表格）：修改申请单号、商家、特约商户号、原结算账户（掩码）、新结算账户（掩码）、申请状态（标签：审核中=蓝 / 审核驳回=红 / 审核成功=绿）、驳回原因、提交时间、完成时间、操作
- **发起入口在【商家列表】已完成进件商家的行内操作【发起结算账户修改】**：行内发起弹窗 → 填写新结算账户（账户类型/开户银行/银行账号）→ 平台侧确认后调微信修改结算账户接口；本页承载记录列表与状态跟踪
- **操作（按状态枚举）**：
   - 审核中 → 【查看申请】（不提供再次提交入口——微信侧审核中无法重复提交）
   - 审核驳回 → 【查看申请】【重新发起】（按驳回原因修改后发起新申请单）
   - 审核成功 → 【查看申请】（显示生效结果，已回写商家记录）
- **进行中拦截**：商家已存在"审核中"的修改申请时，商家列表再次发起会弹窗提示"当前商家有处于进行中的结算账户修改流程，是否查看？"，【前往查看】跳转本列表页并自动筛选该商家

#### 展示规则

1. 状态机为官方三态：审核中 → 审核成功 / 审核驳回；驳回后重新发起为新申请单（与进件驳回同编号覆盖不同）。
2. 每个特约商户**每天限 5 次**提交；审核中无法再次提交。
3. 审核过程中微信可能向新结算账户打款 0.01 元验证；大部分审核 1 个自然日内完成，最长 5 个工作日。
4. 审核成功后自动回写商家主记录的当前结算账户，并同步"结算账户核对"基线。

#### 操作说明

1. 发起修改：选择已完成进件的商家 → 填写新结算账户 → 平台确认 → 微信受理生成修改申请单（审核中）。
2. 审核驳回：按驳回原因修改后【重新发起】（新申请单）。
3. 审核成功：系统回写商家当前结算账户；后续"结算账户核对"以新账户为基线。

#### 异常提示

1. 微信受理失败（如银行信息不合法）：展示接口错误原因，修改后重试。
2. 当日提交达 5 次：提示"今日修改申请已达上限（5 次），请次日再试"。
3. 非已完成进件的商家不可发起修改。

#### 数据写入

写入结算账户修改记录表（修改申请单号、商家、原/新账户、状态、驳回原因、时间、操作人）；审核成功回写商家主记录当前结算账户。

### PC端商家注销

<!-- prototype: src="prototype/pc-merchant-cancel.html?state=list" width="1920" height="1080" title="PC后台原型 · 商家注销 · 列表" -->

#### 页面位置

PC 后台【商家管理】新增【商家注销】。

#### 页面目标

承载商家注销申请记录：前置清账校验、提交微信注销申请、跟踪注销状态（审核中/驳回/成功）。注销成功后商家主状态转"已注销"，可重新进件（新申请单）。

#### 页面结构

- **列表**（表格）：注销申请单号、商家、特约商户号、清账校验结果、注销状态（标签：审核中=蓝 / 审核驳回=红 / 注销成功=绿）、驳回原因、提交时间、完成时间、操作
- **发起入口在【商家列表】已完成进件商家的行内操作【申请注销】**：行内发起弹窗 → 展示清账校验五清单结果（在售券下架/未核销订单清零/待分账清零/余额提清/无改卡中申请）→ 全部通过后上传纸质注销申请书（打印盖章拍照）→ 调官方注销接口；本页承载记录列表与状态跟踪
- **操作（按状态枚举）**：
   - 审核中 → 【查看申请】（等待微信审核；官方状态含等待商户确认时引导商家扫码确认）
   - 审核驳回 → 【查看申请】【重新提交】（换单重新提交，与进件驳回同编号覆盖不同）
   - 注销成功 → 【查看申请】（显示清退资金结果；商家主状态已转"已注销"）
- **进行中拦截**：商家已存在"审核中"的注销申请时，商家列表再次发起会弹窗提示"当前商家有处于进行中的注销流程，是否查看？"，【前往查看】跳转本列表页并自动筛选该商家

#### 展示规则

1. 状态机为官方三态：审核中（REVIEWING）→ 审核驳回（REJECTED，终态）/ 注销成功（CANCEL_SUCCESS，终态）；驳回后换单重新提交。
2. 前置清账校验五清单缺一不可：在售券下架、未核销订单清零、待分账清零、余额提清、无改卡中申请。
3. 注销成功后微信将商户账户遗留资金全额清退；商家主状态转"已注销"，重新进件为全新申请单。
4. 清账校验未通过时【发起注销】按钮置灰，逐项展示未完成项。

#### 操作说明

1. 发起注销：选择商家 → 系统跑清账校验五清单 → 全部通过后上传纸质注销申请书 → 调官方注销接口（生成注销申请单，审核中）。
2. 审核驳回：按驳回原因处理后【重新提交】（换单）。
3. 注销成功：商家主状态转"已注销"；换主体场景由商家列表重新【发起进件】。

#### 异常提示

1. 清账校验未通过：逐项展示"先处理：在售券下架 / 未核销订单 / 待分账 / 余额提现 / 改卡申请"。
2. 微信注销接口报错"该商户当前不允许注销"：提示存在未完结事项，对照清账清单处理。
3. 审核驳回：展示驳回原因；重新提交为换单。

#### 数据写入

写入商户注销记录表（注销申请单号、商家、清账校验结果、纸质申请书图片、注销状态、驳回原因、时间、操作人）；注销成功回写商家主表状态为"已注销"。

   - 退款原因含"商家诱导线下交易"→ 审核弹窗顶部展示飞单线索标记（用户备注与连续出现提示），审核操作与普通审核一致
- **飞单核查弹窗**：退款单信息 + 用户备注 + 处理建议 + 【驳回退款】【同意退款并标记核查】
- **审核弹窗（统一入口，双形态）**：[待审核] 行内只显示【审核】一个按钮；弹窗基础内容 = 订单信息 + 分账信息 + 退款金额（全额）+ 申请原因 + [审核备注]（必填）+ 【审核通过】【审核驳回】；分账状态=已分账时弹窗切换为垫付形态：增加 [平台垫付金额]（必填）、垫付凭证截图（选填）、微信手续费（标注平台承担）与商家解冻收入，底部按钮为【审核通过并完成垫付】【审核驳回】
- **追回弹窗（已退款待追回）**：平台垫付金额 + 商家应追回金额 + [商家实际追回金额] + [商家未追回金额] + [追回时间] + [追回备注] + 【保存追回记录】——追回为一次性动作，无部分追回/全额追回判断
- **失败原因弹窗（退款失败待人工）**：显示微信退款单号、重试次数（上限 3 次）、最近失败原因与建议；弹窗底部【重试】按钮（重新发起微信退款）
- 顶部提示：飞单线索计数（退款原因含"商家诱导线下交易"），需人工核查

#### 展示规则

1. 退款原因含"商家诱导线下交易"时在审核弹窗中标记飞单线索（展示用户备注，提示连续出现将暂停代金券合作）；审核流程与普通审核一致，不设独立弹窗。
2. 过期自动退款由定时任务触发，不占用人工处理量。
3. **退款统计口径（平台视角）**：销售额毛口径不变，退款额独立统计，两者相减得净额；平台垫付总额、已追回金额、未追回金额（= Σ应追回 − Σ实际追回）单独汇总展示；已分账订单不走微信退款，微信手续费不返还，计入平台损失。
4. **商家收入口径（商家视角）**：商家解冻收入原始分账明细保留不改（历史事实）；已分账退款通过商家订单卡追加行表达（红字收入冲减 + 应追回/实际追回/未追回金额与追回备注），不修改历史分账数据。

#### 操作说明

1. 用户申请的未核销退款：系统自动创建退款记录并自动审核通过，直接进入微信退款；平台/系统创建的退款走人工审核流程。
2. 退款按**分账状态**三分支处理——① **付费订单未核销退款**：居民申请自动审核通过（平台/系统创建走人工审核），微信全额退款；② **已核销未分账退款**：居民不可直接退款（联系客服），平台在 PC 创建退款记录走人工审核；审核通过时检查分账状态——仍为待分账则微信退款（成功后分账转「已终止（退款）」），已被每日任务分账则自动转③；③ **已核销已分账退款**：平台垫付弹窗，审核通过即视为垫付完成（订单转已退款、售后转已退款待追回），不调微信退款、不分账回退；后续追回弹窗回填追回金额（纯留痕），[平台损失金额] = 微信手续费 + 商家未追回金额。微信退款失败自动重试最多 3 次，仍失败售后转"退款失败待人工"，订单保持退款中不自动恢复。
3. 驳回需填写原因，用户端可见。

#### 异常提示

退款原路退回失败时提示"退款失败，请人工处理"。

#### 数据写入

更新退款单状态，联动订单状态与分账回退。

## 定时任务

### 每日分账任务

#### 处理对象

[分账状态 = 待分账] 的付费券分账记录（核销时创建）；免费券不适用。

#### 执行时间

后台每日执行一次的内部任务（具体时间按运营与开发约定）；业务页面不展示任务明细。

#### 判断条件

1. 分账状态 = 待分账。
2. 当前时间 ≥ 预计分账日期。

不判断订单主状态（退款过程中订单状态可能已是退款中，但分账记录仍为待分账）。

#### 与退款的关系

1. 退款申请时不改变分账状态、不停止每日分账任务。
2. 退款审核通过时：分账仍为待分账 → 走微信退款（成功后分账转「已终止（退款）」）；分账已成功 → 转平台线下垫付流程。
3. 分账任务内部的暂停、恢复、重试、并发锁由系统内部处理，不在业务页面展开。

#### 处理结果

1. 符合条件的分账记录执行微信分账：抽佣转入平台商户号，剩余资金解冻归商家。
2. 分账记录状态更新为「已分账」，回写 [分账完成时间]。
3. 失败记录进入重试与异常处理（见失败处理）。

#### 失败处理

1. 单笔分账失败：自动重试（原单重试），仍失败分账记录转「分账异常」，进入 PC 分账页人工处理。
2. 任务整体失败：下次定时执行时自动补跑（分账状态仍为待分账的记录继续执行）。

### 过期自动退款任务

#### 执行时间

每日定时扫描，具体时间按运营与开发约定（如每日凌晨）。

#### 处理对象

[待使用] 状态且已超过使用有效期的**付费券**订单（免费券不创建退款记录，仅页面按有效期展示"已过期"）。

#### 判断条件

1. 订单状态为 [待使用] 且订单类型为付费券。
2. 当前时间超过订单记录的有效期结束时间。
3. 不存在进行中的退款单。

#### 处理结果

1. 系统自动创建退款单（[退款发起方]=系统，退款场景=未核销退款），退款原因标记为"过期自动退款"。
2. 系统创建的退款单自动审核通过，走微信全额退款；微信退款失败自动重试最多 3 次，仍失败转人工（售后=退款失败待人工）。
3. 退款成功后订单进入 [已退款]。
4. 向居民发送【退款结果通知】。

#### 失败处理

退款失败订单保留 [退款中] 状态并进入退款异常队列，PC 端【退款管理】标记人工处理。
