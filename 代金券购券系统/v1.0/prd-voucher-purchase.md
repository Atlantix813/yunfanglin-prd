# 代金券购券系统

> 需求文档 · v1.0 初稿（2026-08-10 立项）
> 模式：大型功能版

## 需求背景

### 项目背景

云芳邻当前优惠券体系是"免费领取 / 积分兑换 + 到店核销"，平台无法从发券和核销中产生收入，商家券兑现是平台无法验证的线下事件。商业模式探索已确认：免费券做不了收入，付费券是唯一通路——只有用户在线付钱，平台才有资金控制权，佣金才能自动扣取。

天河金融城共建研讨会确定乐维转为自营运营制，先在小范围跑通"购券—到店消费—核销—分账"的商业闭环。本版本建设付费代金券购券系统，对标掌上生活、大众点评的代金券玩法：商家发布"40 元购 50 元"类代金券，居民在线微信支付购券，到店核销，核销即分账。

代金券与现有优惠券是**两套独立系统**：代金券属于商品 + 订单体系，居民在【我的订单】查看；优惠券仍是直接领券逻辑，在【我的卡包】查看。两者底层执行逻辑不同，本期不做合并。

**资金与进件选型（2026-08-10 立项评审确认，2026-08-18 修正）：** 原定平台收付通（电商收付通）方案，因服务商号下已有越景特约商户（注销也不行）无法开通，**退回普通服务商特约商户模式**——平台入驻普通服务商，商家进件为微信特约商户，用户支付资金进入**商家特约商户号**并冻结，核销后由平台发起分账，将抽佣分到平台商户号，剩余资金解冻归商家。商家侧需完成微信进件（提交资质 + 微信审核 + 商家扫码签约），平台在系统内提供**运营代办进件**功能，不建设商家自助申请页。该选型替代 CRMEB 参考系统"平台统收 + 线下打款"的二清模式，资金由微信托管，合规干净。

## 需求目标

### 核心目标

1. 建立完整的付费代金券交易闭环：商家发券 → 居民购券 → 在线支付 → 到店核销 → 核销即分账。
2. 平台取得真实交易收入：核销完成后平台发起分账，从商家特约商户号将抽佣分到平台商户号，平台得抽佣，商家得实付扣除抽佣后的金额（解冻后按微信侧规则提现）。
3. 资金与退款合规：支付与分账走微信支付普通服务商模式，资金在商家特约商户号冻结托管，退款支持微信原路退回与平台线下垫付两类通道，平台不代收代付商家货款。
4. 商家准入与进件：系统内提供运营代办进件功能，运营录入商家资料并调微信进件接口，跟踪申请单状态后回写特约商户号；不做商家自助申请进件。

### 验收标准

1. 订单主状态只有：待付款、待使用、退款中、已核销、已退款、已关闭。
2. 免费券不创建支付、分账和退款记录；免费券过期页面展示"已过期"（底层状态待使用）。
3. 退款记录创建后，订单进入退款中且不可核销（核销码隐藏、核销接口拒绝）。
4. 未核销订单支持用户和平台发起退款。
5. 已核销订单只能由平台创建退款记录（居民联系客服）。
6. 未核销和已核销未分账均走微信全额退款（不允许部分退款）。
7. 微信退款最多自动重试 3 次。
8. 微信退款失败后订单不自动回退，售后转"退款失败待人工"进入人工处理。
9. 已核销未分账退款成功后，分账记录改为"已终止（退款）"。
10. 已核销已分账退款走平台线下垫付。
11. 已核销已分账不调用微信退款，不做分账回退。
12. 平台垫付完成后订单为已退款，售后状态为"已退款待追回"。
13. 追回不设置部分追回状态，金额纯人工留痕。
14. 分账任务只判断"分账状态为待分账且达到预计日期"。
15. 分账任务不判断订单主状态。
16. PC 支持对三种退款场景发起和处理退款。
17. 居民只有未核销待使用订单显示申请退款。
18. 所有退款记录都能查看对应分账信息（按订单 ID 关联）。
19. 页面按钮、状态标签、流程图与 PRD 完全一致。

## 待确认事项

### 待确认与已确认决策清单

1. 平台服务商商户号申请（前置条件，1-5 个工作日）。**已确认（08-18）**：服务商号下已有越景特约商户（含已注销历史）无法开通收付通 → 退回普通服务商特约商户模式，无需另开新服务商号。
2. 小程序是否被认定为"交易类小程序"（涉及用户确认收货后结算，可能影响分账时效），需技术调研确认。
3. 支付手续费承担方：**已在微信侧开通时选定，系统不暴露配置**（默认建议特约商户承担，最终以开通时选择为准）。
4. 已核销退款（2026-08-30 方案升级）：按分账状态分流——已核销未分账走微信全额退款（分账记录转「已终止（退款）」）；已核销已分账走**平台线下垫付**（不调微信退款、不分账回退），垫付后与商家线下协商追回，追回金额人工留痕，[平台损失金额] = 微信手续费 + 商家未追回金额。
5. 券有效期上限最终取值：**已定（08-18 评审）券有效期默认 22 天**（22 + T+7 = 29 天 < 普通服务商 30 天冻结期，留 1 天缓冲）；分账结算周期 T 默认 7 天可调。
6. 抽佣比例取值与配置粒度（平台级全局配置，支持动态调整、新单生效；是否支持按商家、按券覆盖待确认）。
7. 商家主体类型范围（小微 / 个体户 / 企业等）与相应资质、额度限制。
8. 用户主动申请未核销退款是否默认自动同意，或需运营人工确认。
9. 代金券入口位置确认（首页金刚区 / 服务页 / 市集页）。
10. 建行、收钱吧作为后续支付结算通道的接入方式与时机（本期不依赖）。
11. **商家【已下线】状态（本期不做，先记录）**：商家状态=正常时行内显示【下线商家/上线商家】，【正常 ↔ 已下线】切换；已下线=商家丧失营业能力（涉及优惠券核销等逻辑），本期仅 mark 需求，不开发。
12. 免费券限领与库存：**已定（2026-08-26）**——发布页提供[每人限领张数]（默认 1，复用优惠券模块限领能力），免费券同字段控制；库存由[发售总库存]统一控制。

## 定时任务

### 每日分账任务

#### 处理对象

[分账状态 = 待分账] 的付费券分账记录（核销时创建）；免费券不适用。

#### 执行时间

后台每日执行一次的内部任务（具体时间按运营与开发约定）；业务页面不展示任务明细。

#### 判断条件

1. 分账状态 = 待分账。
2. 当前时间 ≥ 预计分账日期。

不判断订单主状态（退款过程中订单状态可能已是退款中，但分账记录仍为待分账）。

#### 与退款的关系

1. 退款申请时不改变分账状态、不停止每日分账任务。
2. 退款审核通过时：分账仍为待分账 → 走微信退款（成功后分账转「已终止（退款）」）；分账已成功 → 转平台线下垫付流程。
3. 分账任务内部的暂停、恢复、重试、并发锁由系统内部处理，不在业务页面展开。

#### 处理结果

1. 符合条件的分账记录执行微信分账：抽佣转入平台商户号，剩余资金解冻归商家。
2. 分账记录状态更新为「已分账」，回写 [分账完成时间]。
3. 失败记录进入重试与异常处理（见失败处理）。

#### 失败处理

1. 单笔分账失败：自动重试（原单重试），仍失败分账记录转「分账异常」，进入 PC 分账页人工处理。
2. 任务整体失败：下次定时执行时自动补跑（分账状态仍为待分账的记录继续执行）。

### 过期自动退款任务

#### 执行时间

每日定时扫描，具体时间按运营与开发约定（如每日凌晨）。

#### 处理对象

[待使用] 状态且已超过使用有效期的**付费券**订单（免费券不创建退款记录，仅页面按有效期展示"已过期"）。

#### 判断条件

1. 订单状态为 [待使用] 且订单类型为付费券。
2. 当前时间超过订单记录的有效期结束时间。
3. 不存在进行中的退款单。

#### 处理结果

1. 系统自动创建退款单（[退款发起方]=系统，退款场景=未核销退款），退款原因标记为"过期自动退款"。
2. 系统创建的退款单自动审核通过，走微信全额退款；微信退款失败自动重试最多 3 次，仍失败转人工（售后=退款失败待人工）。
3. 退款成功后订单进入 [已退款]。
4. 向居民发送【退款结果通知】。

#### 失败处理

退款失败订单保留 [退款中] 状态并进入退款异常队列，PC 端【退款管理】标记人工处理。

### 支付记录表

#### 表用途

记录每笔订单的微信支付结果，用于订单状态流转与对账。**独立保留（方案 A）**：订单与支付记录非一一对应（支付失败可多次重试，每笔尝试一条流水），且分账、退款、对账均以本表 [微信支付单号 transaction_id] 为锚点。

#### 关键字段

- [支付单 ID]
- [订单 ID]
- [微信支付单号]
- [实付金额]
- [支付状态]：支付中 / 支付成功 / 支付失败 / 已关闭
- [支付时间]
- [回调信息]

#### 字段来源

微信支付回调与订单支付动作写入。

#### 更新时机

发起支付、支付回调、退款时更新。

#### 关联页面或任务

【居民端订单确认页】【居民端支付结果页】【技术实现要点 · 进件与支付】

### 分账记录表

#### 表用途

记录核销后每笔订单的分账执行情况，是平台收入与商家资金的微信侧对账依据。

#### 关键字段

- [分账记录 ID]
- [订单 ID]
- [商家 ID]
- [分账状态]：未创建 / 不适用 / 待分账 / 已分账 / 分账异常 / 已终止（退款）
- [微信支付单号]
- [微信分账单号]
- [实付金额]
- [支付手续费]
- [抽佣金额]
- [商家解冻收入]
- [预计分账日期]
- [分账完成时间]
- [终止原因]：微信退款成功（已终止时填写）
- [失败原因]

#### 字段来源

**核销时创建**（不调用微信分账接口）；金额按订单快照固化，手续费准确值在结算后调「查询订单剩余待分账金额」反推（= 实付 − 可分账净额），核销创建记录时已结算则写入、未结算保持约，分账调度触发时兜底；分账动作由分账调度任务触发平台发起（从商家特约商户号分出抽佣到平台商户号），状态由分账执行结果更新。

#### 更新时机

核销时创建、分账调度触发、分账成功/失败、退款终止时更新。

#### 关联页面或任务

【商家端核销页】【PC端分账与结算页】【PC端退款处理页】【技术实现要点 · 分账流程】

### 退款记录表

#### 表用途

记录所有退款申请与处理结果，区分退款原因，支撑飞单监控。

#### 关键字段

- [退款单 ID]
- [订单 ID]
- [分账记录 ID]
- [退款发起方]：用户 / 平台 / 系统
- [退款场景]：未核销主动退款 / 未核销过期退款 / 已核销未分账退款 / 已核销已分账退款
- [退款前订单状态]：待使用 / 已核销
- [退款金额]（= 订单实付金额，不允许部分退款）
- [退款申请原因]
- [售后状态]：待审核 / 微信退款中 / 已驳回 / 退款失败待人工 / 已退款 / 已退款待追回 / 已追回
- [审核结果]：通过 / 驳回
- [审核备注]
- [审核人]
- [审核时间]
- [微信退款单号]
- [微信退款重试次数]（上限 3 次）
- [微信退款失败原因]
- [平台垫付金额]
- [平台垫付备注]
- [商家应追回金额]
- [商家实际追回金额]
- [商家未追回金额]
- [追回时间]
- [追回备注]
- [微信手续费损失]
- [平台损失金额]（= 微信手续费 + 商家未追回金额）
- [申请时间]
- [完成时间]

#### 字段来源

用户/平台/系统三方均可创建（用户未核销退款自动审核通过，平台/系统创建走人工审核）；一条退款记录冗余本场景全部字段、按需填写；售后状态由退款进度驱动，追回字段组由平台在【PC端退款处理页】人工填写。

#### 更新时机

创建、审核、退款结果、失败重试时更新；已核销已分账退款审核通过即视为线下垫付完成（填写 [平台垫付金额]，售后转「已退款待追回」）；追回协商后填写 [商家实际追回金额]、[商家未追回金额]、[追回时间]，售后转「已追回」（不设部分追回状态，金额纯留痕）；[平台损失金额] = 微信手续费 + 商家未追回金额。

#### 关联页面或任务

【居民端订单详情页】【PC端退款处理页】【过期自动退款任务】

- [主体类型]：小微 / 个人卖家 / 个体工商户 / 企业 / 其他组织

- [超级管理员身份证]
- [超级管理员手机号]
- [结算银行账户信息]
- [进件申请单号]
- [进件状态]：编辑中 / 审核中 / 待账户验证 / 待签约 / 开通权限中 / 已完成 / 已驳回 / 已作废
- [微信特约商户号]
- [支付手续费承担方]：平台 / 特约商户
- [结算卡验证状态]：未验证 / 验证成功 / 验证失败

#### 字段来源

PC 端【商家进件】人工填写并调微信进件接口提交；进件状态（官方枚举）、特约商户号由微信审核结果同步回写。

#### 更新时机

商家录入、提交进件、状态同步、信息维护时更新。

#### 关联页面或任务

【PC端商家进件管理页】【技术实现要点 · 进件与支付】

### 分账任务表

#### 表用途

承载分账的异步任务执行过程，是分账任务状态机的数据实体（参考 CRMEB 分账记账与微信分账接口的异步语义拆分）。**隐藏内部表，不对业务页面展示**；仅开发用于驱动状态机流转与重试治理，任务的异常终态投影为业务视图的"分账异常"标签与【重新分账】入口。

#### 关键字段

- [任务 ID]
- [订单 ID]
- [商家 ID]
- [分账记录 ID]
- [任务状态]：待执行 / 已受理 / 查询中 / 分账成功 / 分账异常
- [微信分账单号]
- [重试次数]
- [错误类型]：可重试 / 终态
- [失败原因]
- [创建时间]
- [执行时间]
- [完成时间]

#### 字段来源

核销事务提交后创建；状态由分账接口受理、查询分账结果、回调结果逐步更新。

#### 更新时机

任务创建、受理、查询结果、重试、完成、异常时更新。

#### 关联页面或任务

【商家端核销页】【PC端分账与结算页】【技术实现要点 · 分账流程】

### 进件申请记录表

#### 表用途

记录商家每次微信进件申请的完整过程（申请单号、审核、签约、账户验证、驳回原因），与商家表扩展字段分工：本表承担申请过程明细，商家表扩展字段承担商家当前进件状态。

#### 关键字段

- [申请记录 ID]
- [商家 ID]
- [微信申请单号]
- [申请单状态]：编辑中 / 审核中 / 待账户验证 / 待签约 / 开通权限中 / 已完成 / 已驳回 / 已作废（与微信 applyment_state 枚举一一对应，单一状态字段直接采用官方枚举，不做归并与附加维度）
- [驳回原因]
- [微信特约商户号]
- [申请提交时间]
- [状态更新时间]

#### 字段来源

PC 端【商家进件】提交进件时创建；审核、签约、验证结果由微信状态同步回写。

#### 更新时机

提交进件、状态同步、驳回重提时更新；一个商家可有多条申请记录，当前有效申请为最新一条。

#### 关联页面或任务

【PC端商家进件管理页】【技术实现要点 · 进件与支付】
